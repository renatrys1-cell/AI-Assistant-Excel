# Qarjy Control — MVP прототипі

> Жұмыс атауы. Баптаулардан өзгертуге болады.
> **DEMO:** барлық компания, адам және сан ойдан құрастырылған. Бұл нақты компанияның (оның ішінде ALTOR) есебі емес. 1С-ке нақты қосылым жоқ (MockConnector).

Қазақстандағы сауда бизнесіне арналған, 1С үстінде жұмыс істейтін қаржылық бақылау және бухгалтерлік аутсорсинг платформасы.
Платформа үш сұраққа жауап береді: **бизнесте не болып жатыр**, **есеп қаншалықты толық және сенімді**, **қандай мәселені кім, қашан шешеді**.

## Іске қосу

```bash
cd qarjy-control
npm install
npm run dev        # http://localhost:5173
npm test           # 27 тест: формулалар, рұқсаттар, оқшаулау, толық сценарий
npm run build      # typecheck + production build
```

Кіру — demo: пароль жоқ, рөлді таңдайсыз. Өзгерістер браузердің `localStorage`-ында сақталады; «Баптаулар → Demo деректер» немесе кіру бетінен бастапқы күйге қайтаруға болады.

## 1. Өнім құрылымы

| Қабат | Қайда | Не істейді |
|---|---|---|
| Домен (таза функциялар) | `src/domain/` | Ақша (тиын, бүтін сан), пайда/ақша/қарыз/төлем күнтізбесі, 14 тексеру ережесі, мәртебе машиналары, KPI, CSV импорт, demo деректер |
| «Backend» API | `src/server/` | Рұқсат (рөл + tenant) әр әдісте, аудит журналы, MockConnector, demo AI, persistence |
| UI | `src/ui/` | React экрандары; деректі тек `Api` арқылы алады |

Негізгі сущностар (`src/domain/types.ts`): Tenant, LegalEntity, Branch, User, Role, Membership, IntegrationConnection, SyncRun, SourceDocument, Transaction, FinancialMetric (есептелетін), CheckRule, Finding, Task, TaskEvent, Review, PeriodClose, ServiceAgreement, Subscription, WorkLog, AuditEvent. Барлық клиенттік жазбада `tenantId` бар.

Мәзір рөлге қарай өзгереді: Басты бет · Қаржы · Мәселелер · Тапсырмалар · Құжаттар · Команда · Есептер · AI көмекші · Қызмет және төлем · Интеграциялар · Баптаулар (+ бухгалтерге «Менің жұмысым», бас бухгалтерге «Бақылау орталығы»).

## 2. MVP көлемі

Іске асырылған: кәсіпкердің басты экраны · қаржының 6 бөлімі (P&L, ақша қозғалысы, қарыздар, төлем күнтізбесі, филиалдар/қойма, иесінің операциялары) · тексерулер орталығы (ереже vs AI күмәні) · тапсырма → тексеру → қайта тексеру → жабу · бухгалтерлер жүктемесі және KPI (формула, кезең, дереккөз) · бас бухгалтердің бақылау орталығы және ай жабу чек-листі · клиент карточкасы және 10 қадамды қосу шебері · тарифтер мен қызметтің үлестік маржасы · demo AI жауаптары · MockConnector және CSV импорт · рөлдер, оқшаулау, аудит · ҚАЗ/РУС интерфейс · телефонға бейімделген.

MVP-ге **әдейі қосылмаған**: production 1С интеграциясы, нақты LLM, банк/құжат интеграциялары, OCR, 1С-ке жазу, кеңейтілген биллинг, автоматты салық тапсыру, автоматты төлем, KPI арқылы жалақыны автоматты өзгерту, басқа салалар.

## 3. Негізгі пайдаланушы жолдары (браузерде тексерілген)

1. **Кәсіп иесі (Ерлан):** Басты бет → «Назар аударуды қажет ететін 3 мәселе» → түсіндірме, ереже, дәлел, құжаттар → «Бухгалтерге тапсыру» (орындаушы мен мерзімді өзі таңдайды).
2. **Бухгалтер (Дәурен):** Тапсырма → Бастау → «1С-те түзетілді» дәлелі → уақыт жазу → Тексеруге жіберу.
3. **Бас бухгалтер (Гүлнар):** Бақылау орталығы → Қабылдау / Кері қайтару (төрт көз: орындаушы өзін қабылдай алмайды) → мәселе «Бекітілді».
4. **Қайта тексеру:** MockConnector 1С-ті қайта оқиды, ереже қайта іске қосылады → «Қайта тексерілді» → «Жабылды» (дәлел мен сәтті қайта тексерусіз жабылмайды).
5. **KPI** орындалған жұмысқа сай жаңарады (күрделілік коэффициентімен).
6. **Қаржы карточкасы → формула → бастапқы операция → 1С құжаты.**
7. **Кезең және филиал сүзгісі** барлық көрсеткішті қайта есептейді.
8. **Жаңа клиент шебері** → оқшауланған tenant, келісім, чек-лист, диагностика тапсырмасы; дерек жоқ кезде көрсеткіштер «Дерек жоқ».
9. **AI жауабынан тапсырма** — жауапты мен мерзімді пайдаланушы бекітеді.
10. **Оқшаулау:** `#/home?tenant=t2` (Ерлан үшін) → «Қолжетімділік жоқ», аудитте `denied`.
11. **Persistence:** бет жаңартылғанда demo өзгерістер сақталады.

Demo сценарийлері деректерде: сатылым өсті, маржа төмендеді (Құрылыс Әлемі) · пайда бар, ақша қарыз бен тауарда (Кеңсе Плюс) · құжат жетіспегендіктен қыркүйек жабылмаған · қайталанған құжат туралы AI күмәні расталмаған («Қате емес» + негіздеме) · тамыздағы теріс қалдық түзетіліп, қайта тексеріліп жабылған · клиент жауабын күтуден кешіккен тапсырма · Айгерімнің жүктемесі > 100% · Береке дүкенінде синхрондау кешіккен, дерек «ескі» деп белгіленген.

## 4. Маңызды болжамдар

- Сомалар ҚҚС-сыз деп алынды; табыс салығы тек ай жабылғанда бухгалтер енгізеді (demo мән, ставка ойдан шығарылмайды).
- Апта/күн кезеңінде ай сайынғы шығындар бөлінбейді → операциялық пайда «бағдар».
- Филиал сүзгісінде банк шоты компания деңгейінде, тек филиал кассасы көрсетіледі.
- Қарыз FIFO бойынша бөлінеді; мерзімі өткен клиент қарызы ақша болжамына кірмейді.
- Тарифтер шартты; бағалар — demo немесе «жеке есептеледі».
- Demo сағаты: 07.10.2026, Asia/Almaty.

## 5. Не жұмыс істейді / не demo

| Жұмыс істейді | Demo / іске асырылмаған |
|---|---|
| Барлық есептеулер, ережелер, мәртебе ауысулары, KPI, рұқсаттар, аудит, CSV импорт (идемпотентті), MockConnector retry және дубльді өткізу | 1С қосылымы (Mock), AI (ережеге негізделген шаблон), кіру (рөл таңдау), MFA (тек белгі), файл жүктеу (метадерек), рұқсат тексеру браузерде, localStorage сақтау |

## 6. Нақты 1С интеграциясына не қажет

1. Пилот клиенттердің конфигурациясы мен нұсқасын тізімдеу (УТ / Розница / БП Казахстан, типтік емес өзгерістер).
2. Бір конфигурацияға адаптер: OData немесе HTTP-сервис (қолжетімділікке қарай), өрістерді сәйкестендіру, бастапқы жүктеу + өзгерістерді инкременттік оқу.
3. Клиент серверіне қолжетімділік (VPN/туннель/агент), тек оқу құқығы бар техникалық пайдаланушы.
4. 1С аудит журналына қолжетімділік (құжат авторын көрсету үшін).
5. Бақылау салыстыруы: 1С-тегі айналым ведомосы vs платформа (ай сайын).
6. Кейінгі кезең — жазу: ұсыныс → тексеру → бекіту → орындау → қайта оқу; бастапқы нұсқа, idempotency key, rollback.

1С лицензиясы — клиенттің жеке шарты, біздің жазылымнан бөлек.

## 7. Production үшін қалған жұмыс

Нақты backend (API + PostgreSQL, row-level security), SSO/пароль + MFA, рұқсатты тек серверде тексеру, құпия кілттер — secrets manager, шифрлау, бэкап және қалпына келтіру, append-only аудит, сақтау/жою саясаты, нақты LLM (минимал дерек, prompt-injection қорғанысы), мониторинг, жүктеме тесттері. Заң талаптары тізімі — «Баптаулар → Production алдында» (жергілікті мамандар тексереді; заң талаптары мен салық мерзімдері ойдан жазылмаған).

## 8. Пилот (3–5 клиент): нені өлшейміз

Пилотқа дейін 4 апта базалық өлшем, содан кейін 8–12 апта платформамен:

| Өлшем | Қалай |
|---|---|
| Есепті дайындауға кеткен уақыт | WorkLog: «Басқарушылық есеп» тапсырмаларының сағаты |
| Ай жабу мерзімі | PeriodClose.closedAt − ай соңы (күн) |
| Қайта түзетулер үлесі | Review: returned / барлық тексеру |
| Кәсіпкердің ақпарат сұрауға кеткен уақыты | Апталық қысқа сауалнама + чаттағы сұраулар саны |
| Клиентке кеткен еңбек сағаты | WorkLog клиент бойынша |
| Қызметтің үлестік маржасы | Айлық түсім − тікелей шығындар (Қызмет экономикасы экраны) |
| Жалғастыру ниеті | Пилот соңында сұхбат + NPS |

Бухгалтер санын қысқарту немесе шығынды азайту туралы алдын ала пайыздық уәде берілмейді — нәтиже тек пилот өлшемдерімен бағаланады.
